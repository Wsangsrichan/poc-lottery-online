## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/digit gaps, badge inner padding |
| sm | 8px | Button padding vertical, list-item row gaps |
| md | 16px | Card inner padding, input field padding |
| lg | 24px | Section padding, between stacked result cards |
| xl | 32px | Page horizontal padding (desktop only) |
| 2xl | 48px | Major section breaks (form → result → table) |
| 3xl | 64px | Bottom safe-area buffer on mobile |

Exceptions:
- Touch targets (buttons, tappable rows): minimum 44px height — source: REQ-07 and iOS HIG
- Digit input cells: 48px height (fits Thai numeral at 20px + padding)
- PrizeBadge chip: 8px vertical / 12px horizontal (py-2 px-3)

## Typography

Font family: `Sarabun, sans-serif` for all roles (Thai + Latin).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px | 400 | 1.5 | Paragraph text, descriptions, history entries |
| Label | 14px | 400 | 1.4 | Table headers, helper text, prize-amount sub-labels |
| Heading | 20px | 600 | 1.2 | Section titles ("ผลการตรวจ", "ผลรางวัลงวดนี้", "ประวัติการตรวจ") |
| Display | 28px | 600 | 1.1 | Win/no-win verdict ("ถูกรางวัล!", "ไม่ถูกรางวัล") + prize amount |

Notes:
- All sizes are mobile-first. Do NOT upscale for desktop — Sarabun reads well at these sizes.
- Prize amount on win state: 28px, weight 600, accent color (see Color section).
- Ticket number rendered at 20px monospace-style (letter-spacing: 0.15em) inside the input for digit clarity.
- Input field font-size minimum 16px to prevent iOS auto-zoom on focus.

## Color

Palette follows the Thai government lottery aesthetic: gold accent on white/light grey surface.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (white) | Page background, card backgrounds |
| Secondary (30%) | `#F5F5F5` (light grey, ~gray-100) | PrizeTable rows (alternating), HistoryPanel background, input field background |
| Accent (10%) | `#D4A017` (warm gold) | Reserved for: win-state verdict text, prize amount, CTA button background, PrizeBadge chip background |
| Win semantic | `#16A34A` (green-600) | "ถูกรางวัล!" verdict icon/border only — not used for text |
| Destructive | `#DC2626` (red-600) | Error state ("ไม่สามารถโหลดข้อมูลได้"), no other use |
| Text primary | `#111827` (gray-900) | All body text, headings |
| Text muted | `#6B7280` (gray-500) | Label text, date strings, helper copy, no-win verdict |
| Border | `#E5E7EB` (gray-200) | Card borders, table dividers, input border |

Accent reserved for:
1. CTA button ("ตรวจสลาก") — background fill
2. Win-state prize amount number (28px display)
3. PrizeBadge chip background
4. Win-state card left border accent stripe (4px)

The win state card uses a combination: green-600 border-left stripe + gold prize amount text + white card background. Do NOT use green as a background fill.

Dark mode: not in scope for v1 POC.

## Component Inventory

Eight components as specified in RESEARCH.md. Visual contract for each:

### 1. CheckForm
- Single centered column, max-width 400px, full-width on mobile
- Input: type="tel", inputMode="numeric", maxLength=6
- Input visual: border-2 border-gray-200, rounded-lg, 48px height, 16px font, text-center, letter-spacing 0.15em
- Input focus state: border-2 border-gold (accent), ring-2 ring-gold/20
- Submit button: full-width, 48px height (touch target), gold background, white text 16px semibold, rounded-lg
- Button disabled state (empty/partial input): opacity-50, cursor-not-allowed
- Ticket number format hint below input: "กรอกตัวเลข 6 หลัก เช่น 123456" — 14px text-gray-500

### 2. CheckResult
Win state:
- Card: white background, border-l-4 border-green-600, rounded-lg, shadow-sm
- Verdict: "ถูกรางวัล!" — 28px semibold, text-gold
- All matched prizes listed as PrizeBadge chips below verdict
- ShareButton rendered below prizes

No-win state:
- Card: white background, border border-gray-200, rounded-lg
- Verdict: "ไม่ถูกรางวัล" — 28px semibold, text-gray-500
- Sub-copy: "หมายเลข {ticket} ไม่ตรงกับรางวัลใดๆ ในงวดนี้" — 16px text-gray-500

### 3. PrizeBadge
- Chip shape: inline-flex, rounded-full, px-3 py-2 (12px/8px)
- Win badge: gold background (#D4A017), white text 14px semibold
- Layout inside CheckResult: flex-wrap gap-2 row

### 4. PrizeTable
- Full-width table on mobile (no horizontal scroll — each prize tier is a row)
- Row structure: prize name (Thai) | winning numbers | prize amount
- Alternating rows: white / gray-100
- Prize name column: 14px text-gray-700 semibold
- Numbers column: 14px monospace-style, letter-spacing 0.1em
- Amount column: 14px text-right text-gray-900
- Table header: 14px uppercase font-semibold text-gray-500, border-b border-gray-200

### 5. DrawDateHeader
- Center-aligned
- "งวดประจำวันที่ {date}" — 16px, weight 400, text-gray-700
- Date format: Thai locale — "1 พฤษภาคม 2566" (use Thai month names)

### 6. HistoryPanel
- Collapsible section (default: collapsed on mobile if >0 entries)
- Section heading: "ประวัติการตรวจ" — 20px semibold
- Grouped by draw date — date as sub-heading 14px text-gray-500
- Each entry: HistoryItem row, tap to re-run check with that ticket

### 7. HistoryItem
- Row: flex, items-center, min-height 44px, px-4, border-b border-gray-100
- Left: ticket number 16px monospace-style
- Right: PrizeBadge (if won) or "ไม่ถูก" 14px text-gray-400
- Tappable full-row, hover state: bg-gray-50

### 8. ShareButton
- Secondary style: border border-gray-300, white background, gray-700 text
- Label: "แชร์ผลลัพธ์" — 16px, weight 400
- 44px height, rounded-lg
- Appears only inside win-state CheckResult
- On tap: navigator.share() → fallback copy URL to clipboard → toast "คัดลอกลิงก์แล้ว" 14px (2 seconds)

### Loading Skeleton
- Matches layout of page: CheckForm placeholder (gray bar) + PrizeTable rows as gray shimmer blocks
- Shimmer animation: animate-pulse (Tailwind built-in)
- Skeleton blocks: rounded, bg-gray-200, heights matching content they replace

### Toast notification
- Bottom-center, fixed position, above safe area
- Small pill: bg-gray-900 text-white 14px, rounded-full, px-4 py-2
- Used only for: clipboard copy confirmation

## Interaction Contracts

### Ticket Input Validation
- Accept: digits 0-9 only (strip non-numeric on input event)
- Max length: 6 digits exactly
- Submit enabled only when length === 6
- On submit: run matchPrizes() client-side (instant — no API call per check)
- Invalid attempt to submit < 6 digits: shake animation on input (keyframes: translate-x ±4px, 200ms)
- No error message text for incomplete input — visual feedback only (red border + shake)

### Loading State (initial page load)
- Page.tsx fetches via ISR. While Suspense fallback active, show loading.tsx skeleton.
- Skeleton is NOT shown on subsequent re-checks (data already in browser).
- Skeleton duration expectation: <500ms typical (ISR cache hit).

### Check Flow (client-side, zero latency)
1. User types 6 digits in CheckForm
2. Submit button activates at 6 digits (no debounce needed)
3. User taps "ตรวจสลาก"
4. matchPrizes() runs synchronously against draw data in props
5. CheckResult renders with win/no-win state
6. History entry written to localStorage via lib/history.ts
7. URL updated to `/?ticket={ticket}` (shallow push — no reload)

### URL Share Flow
- `/?ticket=123456` on page load: auto-populate input AND auto-run check
- ShareButton tap: navigator.share({ url: window.location.href, title: "ผลตรวจสลาก", text: "หมายเลข {ticket} — {result}" })
- Fallback: navigator.clipboard.writeText(url) → show toast "คัดลอกลิงก์แล้ว" for 2 seconds

### Error Boundary
- error.tsx renders when page.tsx fetch fails entirely (static fallback also unavailable)
- Shows error heading + body copy + "ลองอีกครั้ง" button
- "ลองอีกครั้ง" calls router.refresh() (Next.js 15 convention)

### History Panel
- Persisted in localStorage key: `lottery-history` (JSON array, max 50 entries, FIFO eviction)
- Read only in useEffect (never in render — prevents SSR hydration mismatch per RESEARCH.md pitfalls)
- Tapping a history entry: populate CheckForm input + run check (same as manual entry)
- History grouped by draw date — show date as group separator

## Accessibility Contract

- `<html lang="th">` — already in RESEARCH.md architecture (layout.tsx)
- Input: `aria-label="หมายเลขสลาก"`, `aria-required="true"`
- Submit button: descriptive label "ตรวจสลาก" (not "Submit")
- CheckResult: `aria-live="polite"` region so screen readers announce result without focus move
- PrizeTable: proper `<table>` with `<caption>`, `<th scope="col">` headers
- Color is never the ONLY indicator of state (win state also has text verdict, not just color)
- All interactive elements: min-height 44px, min-width 44px (REQ-07)
- Focus ring: visible on all interactive elements (Tailwind `focus-visible:ring-2 ring-gold/50`)

## Tailwind 4.x CSS Tokens

Define in `src/app/globals.css` using `@theme` block (Tailwind 4.x CSS-first convention):

```css
@import "tailwindcss";

@theme {
  --font-sans: "Sarabun", sans-serif;

  /* Spacing scale */
  --spacing-xs: 4px;
  --spacing-sm: 8px;
  --spacing-md: 16px;
  --spacing-lg: 24px;
  --spacing-xl: 32px;
  --spacing-2xl: 48px;
  --spacing-3xl: 64px;

  /* Brand colors */
  --color-gold: #D4A017;
  --color-gold-light: #F5E6B3;

  /* Semantic aliases */
  --color-win: #16A34A;        /* green-600 */
  --color-error: #DC2626;      /* red-600 */
  --color-surface: #FFFFFF;
  --color-surface-2: #F5F5F5;
  --color-border: #E5E7EB;
  --color-text: #111827;
  --color-text-muted: #6B7280;
}
```

These tokens replace all hardcoded color values in component classes.
