### Modified Components

#### LotteryPageClient (modification)
- Adds tab toggle state: `mode` = `'single' | 'batch'` (default: `'single'`)
- Renders `<TabToggle>` above the check form area
- Conditionally renders `<CheckForm>` (single mode) or `<BatchCheckForm>` (batch mode)
- Adds batch result state: `batchTickets: string[]`, `batchResults: BatchTicketResult[]`
- Conditionally renders `<BatchResultSummary>` + `<BatchResultList>` (batch mode)
- Single-mode state (checkedTicket, matches) remains unchanged
- Layout inside the glassmorphism card adapts to active mode

### New Components

#### 1. TabToggle
- Horizontal pill toggle, centered above the form area
- Two options: "ตรวจใบเดียว" (single) and "ตรวจหลายใบ" (batch)
- Container: `inline-flex rounded-full bg-surface-2 border border-border p-xs` (4px inner padding)
- Each tab: `px-md py-sm rounded-full text-sm font-semibold transition-all duration-200`
- Active tab: `bg-gold text-white shadow-sm`
- Inactive tab: `text-text-muted hover:text-text`
- No icons — Thai labels only
- Min touch target per tab: 44px height (enforced via py + text size)
- `role="tablist"` on container, `role="tab"` with `aria-selected` on each tab
- Keyboard: arrow keys move focus between tabs, Enter/Space activates

#### 2. BatchCheckForm
- Single `<textarea>` replacing the single-digit input
- Layout: flex column, same max-w-sm mx-auto px-md as CheckForm
- Textarea visual:
  - `w-full rounded-xl border-2 bg-white/80 px-md py-md`
  - `text-base text-text placeholder:text-text-muted/60`
  - `resize-y min-h-[120px] max-h-[320px]`
  - `transition-all duration-200`
  - Default border: `border-border`
  - Focus border: `border-gold focus-visible:ring-2 focus-visible:ring-gold/30`
  - Error border (invalid input): `border-error/60`
- Placeholder: "วางหมายเลขสลากที่นี่ คั่นด้วยขึ้นบรรทัดใหม่, จุลภาค หรือวรรค"
- Helper text below textarea: 14px text-text-muted, shows "พบ N หมายเลข" (real-time count of extracted 6-digit sequences)
- Parsing feedback:
  - 0 valid numbers: helper text shows "วางหมายเลขสลากที่นี่..."
  - 1-50 valid numbers: "พบ N หมายเลข" in text-text-muted
  - Duplicates detected: "(ซ้ำ X ใบ)" appended in text-text-muted, e.g. "พบ 15 หมายเลข (ซ้ำ 2 ใบ)"
  - Non-6-digit sequences found: "(ตัด X หมายเลขที่ไม่ครบ 6 หลัก)" appended
  - Over limit (>50 unique): "พบ N หมายเลข — ตรวจได้สูงสุด 50 ใบ" in text-error
- Submit button: same style as CheckForm button (gold gradient, full-width, 48px height)
  - Label: "ตรวจรวม"
  - Disabled state: same opacity-40 cursor-not-allowed when 0 valid unique numbers
- No shake animation on submit (unlike CheckForm) — textarea errors are shown via helper text, not shake
- `aria-label` on textarea: "หมายเลขสลากหลายใบ"
- `aria-describedby` on textarea: points to helper text element

#### 3. BatchResultSummary
- Card: `rounded-xl bg-white border border-border shadow-card p-md`
- Appears above BatchResultList with `animate-[fade-in-up_0.3s_ease-out]`
- Content structure (top to bottom):
  1. Heading: "สรุปผลรวม" — 20px semibold text-text
  2. Ticket counts row: flex row with 3 items, gap-sm
     - "ทั้งหมด {N} ใบ" — text-text, 16px
     - "ถูก {W} ใบ" — text-win, 16px semibold
     - "ไม่ถูก {L} ใบ" — text-text-muted, 16px
  3. Total prize amount (only if W > 0):
     - "รางวัลรวม {amount}" — 28px semibold text-gold
     - Amount formatted with th-TH locale + "บาท"
  4. Big win callout (only if any ticket won first or adjacent prize):
     - Inline highlight: `bg-gold/10 rounded-lg px-md py-sm border border-gold/30`
     - Text: "ถูกรางวัลใหญ่!" — 16px semibold text-gold
  5. Per-tier breakdown (only if W > 0, list each tier that was won):
     - `flex flex-wrap gap-xs` row of small items
     - Each item: "{prize_name} x {count}" — 14px text-text-muted
     - Same row layout as PrizeBadge row in CheckResult
- `role="region"` with `aria-label="สรุปผลรวม"`
- If W === 0 (all losing): no prize amount displayed, no breakdown. Card shows counts only + "ไม่ถูกรางวัลใดเลย" — 16px text-text-muted

#### 4. BatchResultList
- Full list of all checked tickets, won tickets first then losing tickets
- Container: `flex flex-col gap-sm`
- Each ticket is a BatchResultItem (see below)
- Won section header (only if W > 0): "ถูกรางวัล ({W} ใบ)" — 14px semibold text-win
- Losing section header (only if W > 0 and L > 0): "ไม่ถูกรางวัล ({L} ใบ)" — 14px text-text-muted
- List animation: items stagger in with `animation-delay` — each item delayed by 50ms from previous, using `animate-[fade-in-up_0.3s_ease-out]` (existing Phase 1 animation)
- Max visible without scroll: all items visible (no virtualized list needed — max 50 items)

#### 5. BatchResultItem
- Row: `flex items-center gap-sm px-md py-sm rounded-lg min-h-[44px]`
- Won state:
  - Background: `bg-win-bg border border-win/20`
  - Left: ticket number — 16px font-mono-style (letter-spacing: 0.15em), text-text
  - Right: flex row of PrizeBadge chips (reuse existing PrizeBadge component)
  - Big win variant (first or adjacent): additional `animate-[glow-pulse_2s_ease-in-out_infinite]` on the row (reuse existing animation)
- Losing state:
  - Background: `bg-surface-2` (no border)
  - Left: ticket number — 16px font-mono-style, text-text-muted
  - Right: "ไม่ถูก" — 14px text-text-muted
- Tappable: no action on tap (batch items are display-only, not re-checkable)
- `aria-label` on each item: "หมายเลข {ticket} — {status}" where status is either prize name or "ไม่ถูกรางวัล"

## Interaction Contracts

### Batch Input Parsing
- On every textarea change (controlled via onChange): extract all matches of `/\d{6}/g` from the value
- Deduplicate: keep only unique ticket numbers (first occurrence wins, case does not matter since digits only)
- Strip non-6-digit: silently ignore any sequences that are not exactly 6 digits
- Real-time helper text update: show count of extracted unique numbers + duplicate/invalid warnings
- No debounce on parsing — regex on <1KB textarea is instantaneous
- Max batch size: 50 unique tickets. If exceeded, show over-limit warning in helper text, disable submit button

### Batch Submit Flow (client-side, zero latency)
1. User pastes or types numbers into BatchCheckForm textarea
2. Real-time helper text shows "พบ N หมายเลข" as numbers are extracted
3. Submit button "ตรวจรวม" enables when >= 1 valid unique number (up to 50)
4. User taps "ตรวจรวม"
5. `matchPrizes()` runs synchronously for each ticket (map over array — total time <1ms for 50 tickets)
6. Results stored in state: `batchTickets[]` and `batchResults[]` (each item: `{ ticket, matches, won }`)
7. BatchResultSummary renders at top with aggregate stats
8. BatchResultList renders below with staggered fade-in-up animation (50ms delay per item)
9. No URL update for batch mode (batch results are not shareable via URL)
10. No localStorage write for batch results (deferred per CONTEXT.md)

### Tab Toggle Interaction
1. User taps "ตรวจหลายใบ" tab
2. Active tab animates to gold pill (background-color transition 200ms)
3. CheckForm fades out, BatchCheckForm fades in (both use existing fade-in-up animation)
4. Any existing single-check result remains in state (switching back restores it)
5. Any existing batch result remains in state (switching back restores it)
6. Mode state persists during the session (does not survive page reload — default is always 'single')

### Batch Result Animation
- BatchResultSummary: `animate-[fade-in-up_0.3s_ease-out]` on mount
- BatchResultList items: staggered animation — `animation-delay: {index * 50}ms`
  - Won items render first (indices 0..W-1)
  - Losing items render next (indices W..W+L-1)
- Big-win items (first or adjacent): additionally apply `animate-[glow-pulse_2s_ease-in-out_infinite]` after initial fade-in completes
- No animation on tab switch back to already-rendered results (results persist in state, re-render without animation)

### Textarea Edge Cases
| Input | Behavior |
|-------|----------|
| Empty textarea | Helper: "วางหมายเลขสลากที่นี่...", submit disabled |
| "123456" | 1 ticket found, submit enabled |
| "123456\n789012" | 2 tickets found |
| "123456, 789012, 345678" | 3 tickets found (comma-separated) |
| "123456 789012 345678" | 3 tickets found (space-separated) |
| "123456\n\n789012" | 2 tickets found (blank lines ignored) |
| "123456\n123456" | 1 ticket found (deduplicated), helper shows "(ซ้ำ 1 ใบ)" |
| "12345" | 0 tickets found, helper: "วางหมายเลขสลากที่นี่..." |
| "12345 789012" | 1 ticket found, helper shows "(ตัด 1 หมายเลขที่ไม่ครบ 6 หลัก)" |
| "1234a6" | 0 tickets found (regex only matches digits) |
| 51+ unique valid numbers | Helper shows over-limit warning, submit disabled |
| Numbers pasted from Excel/copied text with mixed separators | All handled: regex `/\d{6}/g` extracts regardless of separator |

## Accessibility Contract

All Phase 1 accessibility contracts carry forward. Phase 2 additions:

- TabToggle: `role="tablist"` on container, `role="tab"` + `aria-selected` + `tabIndex` on each tab. Arrow key navigation between tabs (Left/Right). Enter or Space to activate.
- Textarea: `aria-label="หมายเลขสลากหลายใบ"`, `aria-describedby` pointing to helper text element with live count
- Helper text: `aria-live="polite"` — screen reader announces count changes as user pastes
- BatchResultSummary: `role="region"` with `aria-label="สรุปผลรวม"`
- BatchResultList: `role="list"` with `role="listitem"` on each BatchResultItem
- BatchResultItem: `aria-label` includes ticket number and win/loss status
- Staggered animation: respects `prefers-reduced-motion` — when reduced motion is preferred, all items render instantly without delay
- All interactive elements (tabs, textarea, button): min-height 44px, focus-visible ring
- Color is never the only indicator: won items have text label ("รางวัลที่ 1" badge) in addition to green border/background
